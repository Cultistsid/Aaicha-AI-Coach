## Top 5 gaps

**1. `coachTurn` failure poisons `coachHistory` — hot path, permanent corruption**

[ClaudeHelper.ts:316-368](file:///Users/cultistsid/Documents/Personal%20Projects/Aaicha/electron/ClaudeHelper.ts) pushes the user message *before* `stream.finalMessage()` resolves. On rejection, the user turn stays with no assistant reply. Next turn pushes another user message → consecutive `user` roles → Anthropic rejects (roles must alternate) → **every subsequent turn fails until `resetCoach`**. The existing test at `ClaudeHelper.test.ts:303` asserts the throw but never inspects history state afterward. Missing: `expect(history to not contain dangling user turn after failed turn)` — and by extension, a failed *image* turn leaving an orphaned base64 blob in history.

**2. `ipcHandlers.ts` — entire file, zero coverage**

328 lines of untested surface, including the exact seam CLAUDE.md flags as the hot path (`coach:turn`). Critical untested behavior:
- `settings:save` → `resetClaude()` + `appState.stt = null` [ipcHandlers.ts:103-121](file:///Users/cultistsid/Documents/Personal%20Projects/Aaicha/electron/ipcHandlers.ts) — race: `stt:start` or `coach:turn` in flight while this tears down. `sttListenerCleanup` still references the dead helper.
- Concurrent `coach:turn` IPC calls — both push user turns into shared `coachHistory` before either resolves → same alternation corruption as #1, one layer up.
- `powerSaveBlocker` lifecycle — `stt:stop` releases the blocker even when `stt:start` failed halfway; blocker leak if `start` throws after `powerSaveBlocker.start`.
- `coach:turn` TOCTOU: `existsSync` passes, file deleted before `readFile` [ipcHandlers.ts](file:///Users/cultistsid/Documents/Personal%20Projects/Aaicha/electron/ipcHandlers.ts) (lines 200-203). Caught, but the `coach:error` send path is unverified.
